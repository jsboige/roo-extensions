- **Le schéma servi par ListTools = `tool-definitions.ts` STATIQUE, pas les objets `*Tool.inputSchema`** (c.188, review #1038) : registry.ts sert `allToolDefinitions` (import statique, #1145 perf) — éditer `conversationBrowserTool.inputSchema` ou le schéma de `listConversationsTool` ne change RIEN de ce que le client voit (ces objets ne sont consommés que par des re-exports barrel). Piège complémentaire : les clés du schéma servi sont **camelCase** (`includeArchives`) et le dispatch passe les args bruts (`as any`, zéro normalisation) → une nouvelle option doit être camelCase bout-en-bout ET déclarée dans `tool-definitions.ts`. Symptôme d'un opt-in mort : la notice de la réponse recommande une option que le schéma ne expose pas = no-op silencieux (pas de validation serveur). Les tests qui appellent le handler directement en camelCase bypassent tout le wire format — seuls des tests dispatch-level voient cette classe de bug. Audit c.191 : la classe a 5 occurrences ; sweep reproductible = zod-shape diff (unwrap ZodEffects `_def.schema`) + handler-read grep (`args.?\.(\w+)` vs clés servies). PR #1041.

- **Un cache sensible à l'appel suivant ne PEUT PAS vivre dans un objet créé à chaque appel d'outil** (c.187, #3256) : le fast path #925 (`messageIndex`/`completeMessages`) semblait implémenté mais `roosyncListAttachments` faisait `new AttachmentManager()` par appel → l'index était jeté à chaque invocation, fast path = code mort dans le chemin réel. Réflexe : vérifier le CYCLE DE VIE de l'objet qui porte l'état mémoire avant de compter sur un "fast path" (pattern sain = singleton `getMessageManager()`/`getUnifiedStoreWriter()`, pas `new` dans le handler tool). Écho : le message sans attachment n'était jamais stampé "complete" → full scan à chaque miss.

- **Test harnais : un PASS qui lit le seed est vacuous** (c.177 2026-08-23, v2.2 sync-settings) : deux itérations d'harnais ont "passé" en lisant le seed intact (1 : seed et cible dans des fichiers différents ; 2 : `pwsh -File` refuse un fichier sans extension `.ps1` → script jamais exécuté, seed jamais modifié). Règle : **tout cas de test doit asserter un changement POSITIF qui prouve que le SUT a tourné** (ex : clé absente du seed → présente après run), pas seulement l'absence du défaut. Cousins : cf. `lesson-narrow-measure-suspect-itself` (mémoire po-2023).

- **URL raw d'un gist = cache CDN ~15 min** (c.177) : après `gh gist edit`, l'URL `/raw/<file>` non-épinglée sert l'ancienne version. Pour vérifier byte-exact : récupérer la version via `gh api gists/<id> --jq '.history[0].version'` puis `/raw/<version>/<file>`. L'API `gists/<id>` est à jour immédiatement (jq ajoute un \n final au contenu extrait).

- **`gh pr create` dans un worktree fork résout la base vers l'UPSTREAM** (c.176 2026-08-23, claudish) : repo = fork `jsboige/claudish` avec remote `upstream MadAppGang/claudish` → `gh pr create` a visé l'upstream public (MadAppGang#218) alors que la branche était poussée sur le fork. Toujours `-R jsboige/claudish` explicite. Fermer la PR erronée immédiatement avec commentaire.

- **VBS harden-launchers ne portent PAS de WorkingDirectory** (c.10 2026-08-15, PR #3119) : `harden-hidden-tasks.ps1` préserve celui de la tâche d'origine (souvent vide → CWD=System32) et `WScript.Shell.Run` ne peut pas en passer. Tout script scheduled via VBS DOIT résoudre son repo root depuis `$PSScriptRoot` (et `Set-Location` si appels git nus ultérieurs), jamais depuis le CWD. Classe d'incident : échec exit-1 avant toute sortie + stderr détruit par `wscript //B` = mort silencieuse nocturne.

- **Empilement RSM po-2023 = cohorte claude.exe orphelins VIVANTS** (c.7 2026-08-15) : le binaire natif `claude.exe` de l'extension VS Code survit au restart de fenêtre (détaché) — chaque vague de restart laisse ses paires claude.exe+RSM (~930 MB, actives : 16/17 burnent du CPU en continu). Kill des process = USER-GATED ; sessions récupérables via JSONL resume.

- **`vi.clearAllMocks()` drop les implémentations** (c.178, PR submod #1030) : sous vitest v3, clearAllMocks reset les `mockResolvedValue` module-scope → les mocks retournent `undefined` → `withRetry` du PgUnifiedStoreWriter avale tout (best-effort, jamais de throw) → échec déroutant "expected undefined to be defined". Pattern canonique (unified-store-writer.test.ts) : ré-établir `mockConnect.mockResolvedValue(...)` dans le beforeEach. Cousin : cf. `lesson-vi-mock-path-depth-silent-noop` (mémoire po-2023). Annexe : withRetry ne throw JAMAIS — un compte de purge ne se fait qu'après COMMIT.

- **Namespace ESM `fs/promises` non configurable** (c.179, PR submod #1032) : `vi.spyOn(fsp,'readFile')` échoue (« Cannot redefine property / Module namespace is not configurable in ESM »). Pattern : `vi.mock('fs/promises', importOriginal)` qui spread `actual` + remplace `readFile` par `vi.fn((...a)=>real(...a))` via ref `vi.hoisted` — délègue par défaut (les autres tests gardent le FS réel), les tests ciblés réinstallent une impl fautive puis restaurent la délégation en afterEach. Voir dashboard.test.ts describe `#3205 résiduel`.

- **`logger.error(msg, {objet})` = angle mort** (c.179, #3205 résiduel) : le 2e param de Logger.error est `error?`, pas metadata — passer `{key, error}` en position 2 → `String()` → `"[object Object]"` dans les logs. 8+ sites touchés (dashboard.ts, index.ts, roosync-config.ts). Signature : `error(msg, err?, metadata?)`.

- **Run local étiqueté « CI » = le vrai défaut** (c.180, #1032) : mes 3 tests nouveaux étaient dans un `describe` TOP-LEVEL frère du principal — pas d'héritage du beforeEach qui pose `ROOSYNC_SHARED_PATH`, afterEach du voisin qui la supprime → rouge UNIQUEMENT sur le runner (pas de `.env` gitignoré pour rattraper). Aucune machine de la flotte ne peut reproduire l'échec sans masquer `.env`. Règles : (1) rapporter « run local » ≠ « check CI » — une valeur juste sous une étiquette fausse ne déclenche aucune vérification ; (2) tout nouveau `describe` top-level dans une suite existante porte son propre beforeEach env (pattern 44 fichiers) ; (3) garde runner-régime : masquer `.env` (`mv .env /tmp/… ; vitest ; mv back`) pour tout test touchant `getSharedStatePath()`. Cousin : cf. `lesson-global-setup-mock-shadows-real-class` (mémoire po-2023).
